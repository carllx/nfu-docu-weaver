# 课程整合方案：使用AI和开发工具构建个人网站

## 📋 课程基本信息

**课程名称**：从零到一：AI辅助的现代Web开发工作流  
**目标学员**：Web开发初学者、设计师转型开发者、个人品牌建设者  
**总时长**：3节课（约255分钟 = 4.25小时）  
**核心成果**：一个结构完整、可持续维护的个人作品集网站

---

## 🎯 整合原则

基于对两份课程记录的深度分析，本方案遵循以下原则：

1. **渐进式学习**：从概念理解 → 系统设计 → 编码实现，符合认知负荷理论
2. **保护心流**：每个模块在90分钟内完成一个完整交付物，避免跨课依赖
3. **理论实践融合**：每个概念都对应具体操作，避免空谈
4. **容错与迭代**：预留调试和反思时间，培养问题解决能力

---

## 📚 三节课模块设计

### **第一节：数字创作的基础设施与AI协作基础** 
**时长**：75分钟  
**核心交付物**：项目简报（Brief.md）

#### 模块结构

**[00:00-15:00] 破冰与愿景建立**
- 课程目标与最终成果展示（实际案例网站演示）
- 现代工作流的革命性：从"个人工匠"到"数字编排者"
- 学员自我介绍与期望收集

**[15:00-35:00] 数字总部的建立**
- **GitHub作为项目中央神经系统**
  - 不仅是代码托管，而是单一事实来源（Single Source of Truth）
  - 项目文件结构的标准化（agents/ docs/ guide/）
  - 下载项目模板并在本地设置工作区
  - **实践**：每位学员创建自己的项目文件夹

- **Markdown：人机协作的通用语言**
  - 为什么AI最喜欢Markdown格式
  - 基础语法速查（标题、列表、粗体、链接）
  - VS Code中的实时预览
  - **实践**：创建第一个.md文件并尝试编辑

**[35:00-55:00] AI智能体的本质与使用**
- **Agent不是工具，是专家团队成员**
  - 通用AI vs 角色化AI：稳定性与专业性的提升
  - agents文件夹中的"专家名册"介绍
    - Analyst（分析师Mary）
    - PM（产品经理）
    - Architect（架构师）
    - UX Expert（UX设计师）
    - Frontend Developer（前端开发者）

- **关键约束：技术栈的限定**
  - 为什么必须限制为 HTML + CSS + JavaScript
  - React/Vue等框架对初学者的认知负担
  - **强制检查清单**：每次与AI对话必须包含的技术约束声明

- **AI治理与科学化使用**
  - 记录使用的模型、版本和参数（可复现性）
  - 推荐的对话平台（DeepSeek vs 智谱 vs GPT/Gemini）

**[55:00-70:00] 与分析师Agent共创项目简报**
- **认知脚手架前置任务**
  - 学员手绘/白板：用户流程草图 + 信息架构
  - 分享与讨论（2-3位学员）

- **多轮对话实战**
  - 初始需求陈述（含技术限制！）
  - 分析师的反问与深挖
  - 头脑风暴的选择与深入
  - 最终指令：生成Brief.md

- **实践**：每位学员与AI完成至少3轮有效对话

**[70:00-75:00] 课程总结与课后任务**
- 回顾：今天建立的三个基础（GitHub、Markdown、Agent）
- **课后作业**：
  1. 完成与Analyst Agent的对话，生成自己项目的Brief.md
  2. 准备至少5张作品素材（图片）放入assets文件夹
  3. 预习：什么是Design Tokens（提供阅读材料）

---

### **第二节：系统化设计与设计令牌系统构建**
**时长**：90分钟  
**核心交付物**：Figma设计系统 + 设计规范文档

#### 模块结构

**[00:00-10:00] 快速回顾与成果检查**
- 学员展示上节课生成的Brief.md（2-3位）
- 常见问题答疑（如AI输出不稳定的处理）

**[10:00-25:00] 设计系统的哲学：从混乱到秩序**
- **为什么需要设计系统**
  - 反面案例：没有设计系统的网站维护噩梦
  - 长期维护 vs 一次性交付的思维转变

- **Design Tokens（设计令牌）：设计的单一事实来源**
  - 什么是Token：变量化的设计决策
  - Token的层级：
    - 核心Token（颜色、字体、间距）
    - 语义Token（primary-color, accent-dark）
  - 案例演示：修改一个Token，全局自动更新

- **Figma中的变量系统实操**
  - 创建颜色变量库
  - 定义间距和字体Token
  - 应用Token到设计元素

**[25:00-50:00] 原子设计理论与组件库构建**
- **原子设计（Atomic Design）框架**
  - 原子：不可再分的设计Token
  - 分子：基础组件（按钮、输入框）
  - 有机体：复合组件（导航栏、卡片列表）
  - 模板与页面

- **在Figma中构建组件**
  - **实践**：创建标准化按钮组件
    - 定义状态（default, hover, active）
    - 使用Token作为属性值
  - **实践**：创建作品卡片组件
  - 组件的实例化与覆盖

**[50:00-70:00] 页面设计与无障碍性**
- **四个核心页面的设计**
  - 首页：品牌身份 + CTA（行动召唤）
  - 作品页：画廊布局 + 灯箱效果
  - 产品页：卡片网格
  - 关于页：个人叙事

- **无障碍性（WCAG）的具体实践**
  - 颜色对比度检查（工具演示）
  - 键盘导航的focus状态设计
  - alt文本的规划
  - **检查清单**：无障碍性验收标准

**[70:00-85:00] 生成设计规范文档**
- **与UX Designer Agent对话**
  - 输入：Brief.md + Figma设计稿链接
  - 生成：Design Specification文档
  - 内容包含：颜色系统、排版系统、间距系统、组件规范

**[85:00-90:00] 课程总结与课后任务**
- **课后作业**：
  1. 完成自己项目的Figma设计系统
  2. 生成Design Spec文档
  3. 与Product Manager Agent对话，生成PRD.md
  4. 预习：JSON数据格式

---

### **第三节：内容建模、编码实现与系统进化**
**时长**：90分钟  
**核心交付物**：可部署的完整网站 + 未来演进计划

#### 模块结构

**[00:00-10:00] 设计成果展示与反馈**
- 学员展示 Figma 设计系统（2-3位）
- 同伴反馈与教师点评

**[10:00-25:00] 内容建模：数据与视图的分离**
- **为什么要内容建模**
  - 硬编码 vs 数据驱动的对比
  - 可维护性与可扩展性的关键

- **创建数据模型**
  - JSON格式介绍
  - 定义作品数据结构
    ```json
    {
      "id": "work-001",
      "title": "作品名称",
      "image_url": "./assets/work-001.jpg",
      "description": "作品描述",
      "year": 2024,
      "tags": ["插画", "数字艺术"]
    }
    ```
  - **实践**：创建artworks.json和products.json

**[25:00-55:00] AI辅助编码实现**
- **准备工作：文档整合**
  - 将Brief.md、PRD.md、Design Spec全部准备好
  - 理解AI需要的完整上下文

- **与Frontend Developer Agent协作**
  - 在VS Code中使用Agent模式
  - 引用多个文档作为上下文
  - 分阶段生成代码：
    1. HTML结构（基于语义化标签）
    2. CSS样式系统（基于Design Tokens）
    3. JavaScript交互（读取JSON数据）

- **实践**：每位学员至少完成首页的代码生成

**[55:00-70:00] 代码理解与调试**
- **CSS变量的应用**
  - 如何将Figma Token转换为CSS自定义属性
  - 示例：
    ```css
    :root {
      --color-accent-dark: #D32F2F;
      --spacing-md: 16px;
    }
    ```

- **JavaScript数据渲染**
  - fetch读取JSON文件
  - 动态生成HTML元素
  - 灯箱效果的实现逻辑

- **无障碍性验收**
  - 使用Lighthouse工具评分
  - 根据检查清单逐项验证

**[70:00-80:00] 部署与版本化思维**
- **部署到GitHub Pages**
  - 仓库设置
  - 部署流程演示
  - 访问测试

- **系统进化思维**
  - 当前版本标记为v1.0
  - 在README.md中编写未来规划（Roadmap）
    - v1.1: 增加博客功能
    - v1.2: 移动端响应式优化
    - v2.0: 引入CMS内容管理

**[80:00-90:00] 破局点与元认知训练**
- **挑战任务**：给出一个存在逻辑矛盾的AI生成PRD
  - 小组讨论：找出问题
  - 提出解决方案

- **反思性讨论**
  - 这套工作流的最大优势是什么？
  - 它可能不适用于哪些场景？
  - 如果AI更强大，哪些环节会被取代？

- **课程总结**
  - 从"学习者"到"创造者"的身份转变
  - 鼓励学员继续迭代自己的网站

## 💡 差异化价值主张

相比传统Web开发课程，本课程的独特价值：

1. **AI First**：不是学完再用AI，而是从第一天就与AI协作
2. **系统思维**：不是教代码片段，而是教设计系统和工作流
3. **认知升级**：从"工具使用者"培养为"系统架构者"
4. **长期导向**：强调可维护性和持续进化，而非一次性交付

---

## 📌 关键成功因素

1. **严格控制每节课的时长**：不超过90分钟，保护注意力
2. **强制性课间作业**：确保知识巩固和成果积累
3. **同伴反馈机制**：每节课都有学员展示环节
4. **教师示范质量**：避免技术故障，提前测试所有流程
5. **学员多样性管理**：为不同基础的学员提供差异化支持

## 📅 实施建议

### 推荐课程间隔
- 第一节 → 第二节：间隔3-5天（完成Brief和素材准备）
- 第二节 → 第三节：间隔5-7天（完成Figma设计和PRD）

- 前70%时间：教师演示 + 同步实践

### 在线vs线下
- **线下优势**：实时指导、技术问题快速解决
- **在线优势**：录屏回放、学员可按自己节奏
- **建议**：线上线下混合，关键演示线下完成

交互过程

- "我想为艺术家 carllllllllx 创建一个个人作品集网站"
