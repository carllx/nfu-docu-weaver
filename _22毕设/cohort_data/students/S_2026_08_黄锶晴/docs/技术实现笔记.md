`这个原理可以被概括为 **“非对称视锥体投影”（Asymmetric Frustum Projection）**，或者更形象地称为 **“屏幕作为传送门”（Screen as a Portal）** 的渲染方法。

### 核心思想转变：从“画”到“窗”

1. **传统3D渲染（画的比喻）**：
    
    - 你设置一个虚拟摄像机在场景中。
        
    - 屏幕就像一块画布，把摄像机看到的内容 **画** 在上面。
        
    - 无论你的头在现实中如何移动，你看到的都只是这幅已经画好的“画”。画本身不会因为你的视点变化而改变透视。
        
2. **桌面VR渲染（窗的比喻）**：
    
    - 虚拟世界是真实存在的。
        
    - 你的电脑屏幕不再是画布，而是你房间墙壁上的一扇 **窗户** 或一个 **传送门**。
        
    - 你的眼睛就是真实的“摄像机”。
        
    - 当你移动头部时，你透过这扇“窗户”看到的虚拟世界景象，其透视关系会随之实时改变，就像你真的在透过一扇窗看外面的风景一样。
        

### 实现原理详解

假设你已经通过某种技术获得了用户眼睛相对于屏幕中心的精确坐标 (eyeX, eyeY, eyeZ)。

#### 第1步：建立世界坐标系

为了计算，我们必须先定义一个统一的坐标系。最简单的方法是：

- **原点 (0, 0, 0)**：设置在 **物理屏幕的中心**。
    
- **X轴**：沿着屏幕水平方向，右侧为正。
    
- **Y轴**：沿着屏幕垂直方向，上方为正。
    
- **Z轴**：垂直于屏幕表面，从屏幕指向用户为正。
    

在这个坐标系中，屏幕本身是一个位于 Z=0 平面上的矩形。

#### 第2步：定义屏幕“窗口”的尺寸

你需要知道物理屏幕在你的世界单位中的尺寸。例如，如果你的屏幕宽50厘米，高30厘米，你可以定义：

- screenWidth = 50.0
    
- screenHeight = 30.0
    
- 屏幕四角坐标为：
    
    - 左下：(-25, -15, 0)
        
    - 右上：(25, 15, 0)
        

#### 第3步：计算非对称视锥体（Asymmetric View Frustum）

这是整个实现的核心。在标准的3D渲染中，视锥体（View Frustum）通常是对称的，摄像机正对着视锥体的中心轴。但在这里，我们的“摄像机”（用户的眼睛）是偏离中心轴的，所以我们需要一个倾斜的、非对称的视锥体。

这个视锥体是一个四棱锥，其顶点在你的眼睛位置 (eyeX, eyeY, eyeZ)，底面则由屏幕的四个角决定。

图形引擎（如OpenGL/DirectX）在构建投影矩阵时，通常需要left, right, bottom, top, near, far这六个参数。它们定义了近裁剪平面上的一个矩形。我们需要根据眼睛的位置来计算这些值。

**计算公式（基于相似三角形原理）：**

1. 首先，确定一个 **近裁剪平面（Near Clipping Plane）** 的距离，这是一个很小但大于0的值，比如 near = 0.1。
    
2. 然后，计算从眼睛位置到屏幕四个边界的向量，并推算出这些向量在近裁剪平面上的交点坐标。
    

- eyeZ 是眼睛到屏幕的距离。
    
- ratio = near / eyeZ
    
- **left**: ( ( -screenWidth / 2 ) - eyeX ) * ratio
    
- **right**: ( ( screenWidth / 2 ) - eyeX ) * ratio
    
- **bottom**: ( ( -screenHeight / 2 ) - eyeY ) * ratio
    
- **top**: ( ( screenHeight / 2 ) - eyeY ) * ratio
    
- **near**: 0.1 (设定值)
    
- **far**: 1000.0 (设定值，足够远即可)
    

#### 第4步：应用变换

有了上述参数后，你需要做两件事来完成渲染：

1. **构建视图矩阵（View Matrix）**：
    
    - 这很简单，就是将虚拟摄像机的位置设置在用户的眼睛位置 (eyeX, eyeY, eyeZ)。
        
    - 让摄像机始终朝向屏幕中心 (0, 0, 0) 或者更准确地说，是眼睛位置在Z=0平面上的投影点 (eyeX, eyeY, 0)，以确保视角正确。
        
2. **构建并应用投影矩阵（Projection Matrix）**：
    
    - 使用上一步计算出的 left, right, bottom, top, near, far 值来构建一个非对称的投影矩阵。大多数3D库和引擎都有直接创建这种“Frustum”矩阵的函数。
        

当这两步完成后，渲染出的画面就是用户在当前位置透过屏幕“窗口”应该看到的正确透视景象。

### 在 TouchDesigner / vvvv 等平台的应用指引

这些视觉化编程平台完美支持这种操作，因为它们允许你对渲染管线的每个环节进行精细控制。

**通用线索：**

1. **找到Camera组件/节点**：在你的平台中，找到控制渲染视角的Camera组件（例如TouchDesigner的Camera COMP）。
    
2. **寻找自定义投影矩阵功能**：
    
    - 在**TouchDesigner**中，Camera COMP有一个“Projection”参数。将其设置为 **"Custom"**。
        
    - 这会允许你手动提供一个自定义的View Matrix和Projection Matrix。
        
3. **获取头部坐标**：通过你选择的追踪技术（Kinect, Webcam with OpenCV, etc.）获取 eyeX, eyeY, eyeZ。
    
4. **计算矩阵**：
    
    - **视图矩阵**：使用一个Look At节点/功能，将from（或eye）设为你的头部坐标，将to（或target）设为(0, 0, 0)。
        
    - **投影矩阵**：你需要找到一个可以根据left, right, bottom, top, near, far六个参数生成投影矩阵的节点或编写一小段脚本。在TouchDesigner中，你可以用Script CHOP或Script SOP配合Python的numpy库来计算这个4x4矩阵。
        
5. **连接数据流**：将计算出的视图矩阵和投影矩阵连接到Camera组件的相应输入端。
    

**总结：** 你的任务流程将是：  
头部追踪坐标 -> 计算非对称Frustum参数 -> 生成投影矩阵 -> 应用到Camera。  
同时，  
头部追踪坐标 -> 生成视图矩阵 -> 应用到Camera。

只要你能在你的平台中找到设置自定义视图和投影矩阵的方法，你就可以完美地复现这个效果。

一、最小可行实现（MVP）路线图


目标：在单屏、单用户场景下，基于屏幕三点与眼点，实时构建非对称投影与视图矩阵，避免窗口违背，并确保基本的交互与后处理可用。
输入：
屏幕三点 pa（左下）、pb（右下）、pc（左上），单位为米或厘米，处于同一追踪坐标系。
眼点 pe（同坐标系），每帧更新。
near、far（建议near为5–20毫米量级，far按场景设定；如采用反向Z则另行处理）。
输出：
视图矩阵 V（以眼点为原点，以屏幕基向量为轴的变换）
非对称投影矩阵 P（偏轴视锥）
可选：斜近裁面或模板裁剪，防止“窗口违背”

二、核心数学（Kooima三点法，简洁版）


构建屏幕基向量：
vr = normalize(pb - pa) // 屏幕右向
vu = normalize(pc - pa) // 屏幕上向
vn = normalize(cross(vr, vu)) // 屏幕法线
眼点相对屏幕几何：
va = pa - pe
vb = pb - pe
vc = pc - pe
d = dot(va, vn) // 眼点到屏幕平面的有符号距离，要求d>0（眼在屏幕后方）
非对称投影边界（以near为近裁距离）：
left = near * dot(vr, va) / d
right = near * dot(vr, vb) / d
bottom = near * dot(vu, va) / d
top = near * dot(vu, vc) / d
视图矩阵（将世界点变换到以眼为原点、以屏幕为基的坐标系）：
R = [ vr.x vr.y vr.z 0
vu.x vu.y vu.z 0
vn.x vn.y vn.z 0
0 0 0 1 ]
T = 平移矩阵，将原点移到pe（即-pe）
V = R * T
注意：不同API的前向轴约定不同（OpenGL通常相机前向为负Z）。若出现前后颠倒，取vn或-vn并统一投影构造的符号。
投影矩阵P（标准透视偏轴形式）：
row(0): 2*near/(right-left), 0, (right+left)/(right-left), 0
row(1): 0, 2*near/(top-bottom), (top+bottom)/(top-bottom), 0
row(2): 0, 0, -(far+near)/(far-near), -2farnear/(far-near)
row(3): 0, 0, -1, 0
这是典型OpenGL风格的行列式写法；DirectX/Vulkan的深度范围与行/列主序会不同，落地时需按平台改写。

三、斜近裁面（必备的“窗口违背”解决方案）


矩阵修改法（Eric Lengyel）：
给定屏幕在相机空间的平面方程 plane = [A, B, C, D]（相机空间下，屏幕平面法线与位置可从V中得到，将世界平面变换到相机空间）。
选取q为裁剪空间角点：q = [sign(A), sign(B), 1, 1]
计算c = inverse(P) * q
scale = 2.0 / dot(plane, c)
用plane*scale替换投影矩阵的第三行（或第三列，依平台主序），并做必要的加项（不同约定下存在c.z+1等微调项）。若不确定，建议采用下述替代法。
替代法：GPU原生裁剪距离（更稳妥、更跨平台）
在顶点/几何着色器输出SV_ClipDistance（HLSL）或gl_ClipDistance（GLSL），值为点到屏幕平面的有符号距离。
显卡会在栅格化前进行裁剪，近似达到斜近裁面的效果，避免直接修改投影矩阵带来的平台差异与易错点。
模板缓冲法（Portal遮罩）：
先渲染屏幕四边形，写入模板值1；
主场景仅在模板=1区域绘制；
适合快速验证与UI遮罩，缺点是不能阻止屏幕外物体对深度的影响，建议与斜近裁面配合。
