# 基于证据的智能体课程设计法 (Agentic Course Design)

## 1. 核心理念与定位 (Core Philosophy)

本方法论旨在利用大语言模型（LLM）进行课程研发，但坚决反对将其视为“全自动生成的魔法”。其核心判断如下：

> **用户当前判断：**
> NotebookLM 在这里仅仅是“资料室和证据库”，负责把每本书讲清楚，而不是自动写课程的老师。
> 课程大纲不能凭空想象，每个模块都必须回到教材证据和清晰的教学目标。
> 最终“这东西能不能教”必须由人类讲师来判断，而非花哨的多 Agent 扮演游戏。

在此框架中，机器解决**事实检索与低风险结构编排**，人类解决**价值取舍与最终裁决**。

## 2. 角色定义与隔离 (Roles & Boundaries)

系统由三类核心角色构成，严格隔离“证据获取”、“架构综合”与“最终裁决”：

### A. 教材证据代理 (Sub-Agent)
- **定位：** 单一教材的受限代表（固定身份，每轮重新取证）。
- **职责：** 只能依据指定的教材（NotebookLM 限定 `source_ids`）发言。找不到依据时必须弃权。
- **约束：** 严禁将外部知识说成教材观点；提出的每一项主张必须附带原文出处。

### B. 主控 Agent (Controller)
- **定位：** 会议状态机、决策路由器与课程架构师。
- **职责：** 负责“谁发言、何时发言、谁批评谁、何时停止”。
- **工作机制：** 不直接宣读教材，而是将教材证据代理的观点进行综合；判断是否需要发起关系检查；检查收敛条件。

### C. 人类讲师 (Human-in-the-loop)
- **定位：** 价值与可行性裁决者。
- **介入节点：** 
  - **输入关卡：** 提供课程方向、约束、并确认教材映射。
  - **异常干预：** 当教材之间存在不可调和的底层冲突时，由人类决定取舍（例如：项目优先还是理论优先）。
  - **最终验收：** 裁决综合出的课程大纲是否具备教学可行性。

## 3. 最小可行工作流 (MVP Workflow)

为了避免过度工程化，本方法采用“固定阶段骨架 + 动态议程”的最小可行工作流。

### 阶段一：输入与建档 (Initialization)
1. 人类提供简短课程 Brief，包含五项最低输入：面向哪些学生、总课时与每周安排、最终希望学生完成什么、硬约束（如场地设备）、已明确反对的教学方式。
2. 主控 Agent 建立教材到 NotebookLM `source_ids` 的映射。开始提问前，必须核验 `source_id` 存在、标题与教材一致、来源已处理完成。最后交由人类确认。
3. **明确隔离**：各教材提取任务必须使用相互隔离的 Notebook 或 conversation，避免聊天历史互相污染。

### 阶段二：单书提取 (Evidence Extraction)
1. 主控指派各《教材证据代理》向 NotebookLM 提问。
2. 《教材证据代理》使用统一的证据贡献卡返回结果（每本教材最多 3–5 项）。
   - 每项包含：教材主张、原文证据与位置、可支持的课程问题、可能转化的教学活动、适用边界。
   - 必须严格区分“教材明确主张”与“教学转译建议”。
   - 找不到直接证据时必须写“弃权”，不得使用外部知识补齐。

### 阶段三：跨书比较与一次针对性检查 (Cross-book Comparison)
1. 主控先制作关系矩阵（寻找竞争同一位置、导向不相容或关键证据定位不清的内容）。
2. 只有发现上述冲突情况，才发起一次性关系检查。教材证据代理只能根据自身教材回复：支持、补充、张力、无证据/无关。
3. **收敛条件**：最多进行一轮关系检查。如果没有新的引用证据则立即停止。

### 阶段四：架构合成与收敛 (Synthesis)
1. 主控 Agent 根据所有有证据的提案合成课程大纲初稿。不强制要求所有教材必须进入最终大纲。如果证据不足，应输出“知识缺口”，不要强行合成完整模块。
2. **模块要素**：每个模块必须至少包含：模块目标、教材依据、核心活动、学生产出、时间分配、课程设计决定或待验证假设。
3. **明确区分**：必须将“教材依据”与主控作出的“课程设计决定”（如模块顺序、课时分配、活动形式）分开明确标示。

### 阶段五：人类裁决 (Human Judgment)
1. 主控将最终大纲提交给人类讲师。
2. 人类讲师进行关键证据抽查：核查决定课程结构的 3–5 条“承重证据”。
3. 判断真实课堂的活动可行性，时间、学生基础和材料条件是否匹配，最终选择采纳、局部修改或退回。
