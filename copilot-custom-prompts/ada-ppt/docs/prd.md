# "Instructor" AI Agent (Ada) 产品需求文档 (PRD)

版本: 1.0

作者: B-MAD PM

## 1. 目标与背景 (Goals and Background Context)

### 1.1. 目标 (Goals)

- **对于教师**: 根本性地减少创建高质量教学演示文稿的时间和认知负担。
    
- **对于学生**: 提供一种视觉优先、引人入胜且易于理解的学习体验。
    
- **对于产品**: 创建一个可扩展的、基于教学法原则的内容转化引擎。
    

### 1.2. 背景 (Background Context)

本项目旨在解决当前教学演示文稿普遍存在的“信息过载”和“缺乏互动性”的问题。通过引入 AI 驱动的教学设计原则，我们将原始的、未经组织的文本材料，转化为服务于“教学”和“学习”双重目标的结构化演示文稿。`agent` Ada 的设计核心是分离关注点：为学生呈现最精炼的视觉信息，同时为教师提供足够的支持性备注，从而优化整个教学交付体验。

## 2. 需求 (Requirements)

### 2.1. 功能性需求 (Functional Requirements)

- **FR1**: 系统必须能接收用户提供的任意长度的原始文本作为输入。
    
- **FR2**: 系统必须遵循“一页一思想”原则，将输入文本自动分割成多个逻辑独立的幻灯片内容块。
    
- **FR3**: 系统必须能够分析每个内容块，并将其分类为 [艺术理论] 或 [技术/代码] 两种类型之一。
    
- **FR4**: 系统必须根据内容块的类型，向用户推荐一个最优的设计原则（[技术/代码] -> [P5]或[P7]；[艺术理论] -> [P1]或[P2]）。
    
- **FR5**: 系统必须等待用户确认设计原则。用户可以选择接受推荐、从[P1]-[P8]中指定一个，或在不选择的情况下继续（此时系统将采用默认推荐）。
    
- **FR6**: 对于每个内容块，系统必须生成一个 `Presentation` 部分，该部分包含：
    
    - **FR6.1**: 一个将核心概念转化为设问句的标题 (`[H]`)，长度不超过15个词。
        
    - **FR6.2**: 2到4个核心关键词/短语 (`[KP]`)，每个不超过5个词。
        
    - **FR6.3**: 一个格式为 `![bg fit left:50% vertical]()` 的图片占位符。
        
- **FR7**: 对于每个内容块，系统必须生成一个 `SpeakerNote` 部分，该部分包含：
    
    - **FR7.1**: 1-2句自然的过渡句 (`[Opener]`)。
        
    - **FR7.2**: 针对 `Presentation` 部分的每个关键词，提供一个对应的扩展解释或问题 (`[Expansion]`)。
        
    - **FR7.3**: 从原文中提取的一个核心论据 (`[Evidence]`)。
        
    - **FR7.4**: （可选）一个明确的教学活动指令 (`[Action]`)。
        
    - **FR7.5**: 一段符合规范的、用于 AI 图片生成的英文提示词 (`[V-Prompt]`)。
        
- **FR8**: 系统必须将每个 `SpeakerNote` 部分的全部内容包裹在 HTML 注释 (`<!-- ... -->`) 中。
    
- **FR9**: 系统必须将所有处理过的内容块整合成一个单一的、格式有效的 Marpit Markdown 文档。
    
- **FR10**: 最终输出的文档顶部必须包含一个Marpit元数据块，并正确设置 `theme: NFUPPT`。
    
- **FR11**: 在除最后一张幻灯片外的每张幻灯片末尾，系统必须插入一个幻灯片分隔符 `---`。
    

### 2.2. 非功能性需求 (Non-Functional Requirements)

- **NFR1 (样式约束)**: 系统绝对禁止在输出中定义任何自定义样式（如主题、颜色、背景、字体）。
    
- **NFR2 (格式约束)**: 系统绝对禁止在输出中使用 Markdown 表格格式。
    
- **NFR3 (标签约束)**: 最终输出的 Markdown 内容中不得包含任何结构性标签（如 `[Presentation]`, `[SpeakerNote]`, `[H]` 等）。
    
- **NFR4 (性能)**: 对于一篇5000字的输入文本，系统应在60秒内完成完整的演示文稿生成。
    
- **NFR5 (可靠性)**: `create-presentation` 核心任务的执行成功率必须高于99%。
    

## 3. Epic 与 Story 结构

### **Epic 1: 核心演示文稿生成引擎**

- **Epic 目标**: 实现从原始文本输入到最终 Marpit 演示文稿输出的端到端自动化工作流，确保所有功能需求和约束都得到满足。
    

#### **Story 1.1: 内容接收与智能预处理**

- **用户故事**: 作为一个 `Instructor` `agent`，我希望能接收用户的原始文本，并将其智能地分页和分类，以便为后续的教学法优化做准备。
    
- **验收标准**:
    
    1. 能成功接收并读取用户提供的文本内容。
        
    2. 能根据“一页一思想”原则将文本分割成多个内容块。
        
    3. 能为每个内容块正确地打上 `[艺术理论]` 或 `[技术/代码]` 的标签。
        
    4. 分割和分类的结果以内部结构化数据形式存在，为下一步做好准备。
        

#### **Story 1.2: 互动式设计原则选择**

- **用户故事**: 作为一个 `Instructor` `agent`，我希望能根据内容类型向用户推荐合适的设计原则，并等待他们的决定，以确保最终的演示文稿符合他们的期望。
    
- **验收标准**:
    
    1. 当内容类型为 `[技术/代码]` 时，优先推荐 `[P5] 6x6法则` 或 `[P7] 可读性原则`。
        
    2. 当内容类型为 `[艺术理论]` 时，优先推荐 `[P1] 少即是多` 或 `[P2] 故事导向原则`。
        
    3. 系统会暂停执行，并以指定的推荐话术向用户提问。
        
    4. 系统能正确处理用户的选择（接受、指定其他、或默认继续）。
        

#### **Story 1.3: 单页幻灯片内容生成**

- **用户故事**: 作为一个 `Instructor` `agent`，我希望能为一个内容块生成包含 `Presentation` 和 `SpeakerNote` 两部分的完整结构化内容，确保学生和教师的需求都得到满足。
    
- **验收标准**:
    
    1. 成功生成符合 FR6 所有子项规范的 `Presentation` 部分。
        
    2. 成功生成符合 FR7 所有子项规范的 `SpeakerNote` 部分。
        
    3. `V-Prompt` 提示词必须是英文，并包含核心概念、艺术风格、情感氛围和方形比例。
        
    4. `Expansion` 必须与 `KP` 关键词一一对应。
        

#### **Story 1.4: 最终 Marpit 文档整合与输出**

- **用户故事**: 作为一个 `Instructor` `agent`，我希望能将所有生成好的幻灯片内容整合成一个单一、格式正确的 Marpit 文件，以便用户可以直接使用。
    
- **验收标准**:
    
    1. 最终的输出文件以指定的 Marpit 元数据块开始。
        
    2. 所有 `SpeakerNote` 部分都被正确地包裹在 `<!-- ... -->` 中。
        
    3. 每张幻灯片之间都有一个 `---` 分隔符（最后一张除外）。
        
    4. 最终输出内容干净，不包含任何中间过程的标签（如`[H]`, `[KP]`）。
        
    5. 严格遵守 NFR1 和 NFR2，不产生任何自定义样式或 Markdown 表格。
        

## 4. 后续步骤 (Next Steps)
