# Project Charter：Obsidian LLM Wiki 与项目知识系统

## 1. 项目初衷

在现有复杂 Obsidian Vault 上，逐步建立一个由人和 Agent 共同维护的长期知识系统。

该系统借鉴 Andrej Karpathy 的 LLM Wiki 思想：

- 原始资料作为 Sources 保存；
- Agent 将多个来源编译为可持续更新的 Wiki；
- 查询优先读取 Wiki，必要时回查 Sources；
- 新材料能够更新已有概念、人物、作品和方法页面；
- 所有重要知识保持可追溯；
- 用户保留研究、创作和教学的最终决定权。

## 2. 当前现实目标

第一阶段真实项目是：

`《造物与创格》八周实践课程`

预计在 10 月实施，暑假期间完成备课。

需要支持：

- 课程理论研究
- 书籍摄入
- 艺术家与作品案例
- 八周课程结构
- 学生活动与作业
- 教师判断与课程决定
- Markdown 与思维导图协作
- 课程资料的历史维护

## 3. 长期适用领域

系统未来需要支持：

- 当代艺术
- 数字媒体艺术
- 游戏设计
- 数字媒体剪辑
- 建模与数字雕刻
- 网页交互产品
- 交互装置
- 课程设计
- 游戏制作与运营探索

这些领域不是互斥文件夹，而是通过概念、方法、媒介、人物和项目互相连接。

## 4. 核心原则

1. 项目驱动，知识共享。
2. Sources 不等于真理，而是不可随意改写的证据材料。
3. Wiki 是可持续修订的综合知识。
4. Project 保存具体课程、作品与任务。
5. Personal Thinking 保存用户判断、假设和创作意图。
6. Agent 负责整理地图，人负责方向与最终决定。
7. 不为了形式上的整齐而破坏已有知识关联。
8. 先用小规模 Pilot 验证能力，再扩大自动化。
9. 暂不建设全库 RAG；只有检索测试证明必要时才评估。
10. 书籍是知识来源，不是 Skill；Skill 是处理书籍的方法。

## 5. 当前非目标

目前不做：

- 全库自动分类
- 批量移动根目录笔记
- 自动重写旧笔记
- 自动合并同名概念
- 全库向量数据库
- 让 Agent 无审核地长期自动运行
- 把每一本书包装成独立人格或无依据的作者模拟
