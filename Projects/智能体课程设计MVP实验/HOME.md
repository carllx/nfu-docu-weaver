# 智能体课程设计MVP实验

## 项目目标
验证基于 NotebookLM 作为证据底座，通过多智能体协作（教材证据代理+课程主控）生成课程大纲的可行性，并测试其是否能有效降低幻觉。

## 当前实验范围
基于最简的 5 步工作流（输入 -> 单书提取 -> 一次关系检查 -> 架构合成 -> 人类裁决），验证其能否在不使用复杂 Python 状态机和 JSON Schema 的情况下，依靠原生 Agent 产出具备教学可行性的大纲。

## 已完成实验
执行过一次初始的“最小可行框架”生成实验。成功在人工干预最少的情况下，综合教材产出了一个具有 4-6 个模块的课程大纲初稿。

## 初步观察
本次实验初步显示：
1. **降低无依据陈述、错误归因和错误综合风险**：限定来源与引用要求有助于降低无依据陈述和错误归因风险，但不能完全消除理解与综合错误。
2. **人类的不可替代性**：Agent 能协助整理教材贡献和潜在冲突，教学可行性仍必须由人类讲师裁决。
3. **精简架构易于执行**：与此前更复杂的运行时设想相比，精简流程在本次实验中更容易执行。

## 被放弃的方案
1. **完全自由的多 Agent 辩论**：因为可能导致无限追问、脱离教材和调用成本失控而被放弃，改为由主控统一收口的“一次针对性关系检查”。
2. **构建复杂的 Python 编排引擎与 Local LLM 适配器**：被用户明确叫停，判定为偏离最初验证目标的“过度工程化”。

## 已确认决定
1. 保留 5 阶段精简架构，不再扩展更复杂的机器治理框架。
2. 所有教材证据代理的输出必须规范为 3-5 张统一格式的“证据贡献卡”。
3. 主控制作最终大纲时，必须将“教材依据”和“设计决定”分开排版。

## 未解决问题
- 虽然实验证明了基础可行性，但该方法论的通用性如何？（目前仅在一次简单实验中成功）。
- 若面对超过 10 份长篇核心教材，当前的 Prompt 策略是否会导致主控合成时的“上下文灾难”？

## 下一步实验
1. **立刻用一项真实的课程设计任务运行一次**（如《造物与创格》项目）。
2. 在该新实验中验证刚确立的“课程 Brief”五项硬约束是否能够成功挡住无效的大纲生成。
3. 检查人类抽查“3-5条承重证据”在真实工作流中的时间成本。
